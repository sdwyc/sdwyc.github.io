# 迭代日志（debug_log）使用约定

本目录用于记录 **每次文件修改** 的迭代日志，便于后续排查、回溯与对比。

## 文件组织

- 按事件/任务分文件：`YYYY-MM-DD-<简短主题>.md`
  例：`2026-11-20-docker-本地部署修复.md`
- 同一天的不同任务各自独立成文件，不混写。
- 只追加、不改写历史条目；需要更正时在条目下加 `> 更正：...`。

## 每条记录的固定结构

```markdown
## HH:MM — <一句话摘要>

- **文件**：`相对路径`（可多个）
- **触发问题**：现象/报错关键行
- **原因分析**：为什么会出现
- **改动做法**：具体改了什么（关键 diff 或要点）
- **验证方式**：如何确认生效（命令 + 结果）
- **影响面 / 回滚**：需要注意的地方、如何撤销
```

## 记录原则

1. **只记录真实发生的改动**，不写计划、不写未落地的方案。
2. **报错要贴关键行原文**（如 `cannot load such file -- ostruct`），方便日后全文搜索。
3. **时间用本地时间**（`YYYY-MM-DD HH:MM`，CST）。
4. **验证结果要可复现**：写清命令与返回（状态码、输出摘要）。
5. 涉及临时绕过（如 `dangerouslyDisableSandbox`、`network: host`）必须写明，避免被当成长期方案。
